# 软件中心生态生态软件包配置文件贡献指南

本文面向社区开发者，介绍如何引入一个新的生态软件包编写配置文件。该仓库用于发布在 [openEuler软件中心](https://easysoftware.openeuler.openatom.cn/) 上安装验证通过的生态软件包，收录软件包的基本信息与在不同 openEuler 版本上的支持验证情况。

## 一、目录结构

每一个 生态软件包在 `packages/` 目录下拥有独立的子目录，目录名即软件包名，其中固定包含两个配置文件：

```
packages/
└── <package-name>/
    ├── package.yml              # 软件包基本信息（包名、描述、来源、使用方法等）
    └── supported-versions.yml   # 软件包在不同 openEuler 版本/架构上的支持验证情况
```

例如：

```
packages/
└── zstd/
    ├── package.yml
    └── supported-versions.yml
```

新增一个软件包，就是新建 `packages/<package-name>/` 目录并按下述规范补齐这两个文件。

## 二、`package.yml` 字段说明

`package.yml` 描述软件包的元信息。字段如下：

### 基本信息（必填）

| 字段 | 说明 | 示例 |
| --- | --- | --- |
| `name` | 软件包名，需与目录名一致 | `zstd` |
| `category` | 软件分类，当前已有分类如下，可新增：`others`、`hpc`、`storage`、`database` | `others` |
| `type` | 软件包类型分类：`RPM`、`应用镜像`、`CONDA`、`OEPKG`、`PIP`、`NPM`、`源码安装` | `CONDA` |
| `description` | 软件包简要描述（英文） | `Zstandard - Fast real-time compression algorithm` |
| `license` | 许可证标识（推荐使用 SPDX 标识） | `BSD-3-Clause` |
| `homepage` | 软件官网或项目主页 | `http://www.zstd.net` |
| `maintainer` | 维护者账号（gitcode/gitee 用户名） |  |
| `maintainer-email` | 维护者邮箱 | `xxx@xx.com` |
| `usage` | 使用说明，多行 Markdown 文本，通常软件下载/源配置、创建环境(可选)、安装软件包、软件配置应用 等步骤 | 见模板 |

> `usage` 使用 YAML 的块标量语法 `usage: |`，其后的缩进内容会原样保留为 Markdown 文本。

## 三、`supported-versions.yml` 字段说明

`supported-versions.yml` 记录软件包在各 openEuler 版本、各软件版本、各 CPU 架构上的验证支持情况，采用三层嵌套结构：

```
<openEuler 版本>:
    <软件包版本>:
        - <架构>
```

- **openEuler 版本**：如 `24.03-LTS`、`24.03-LTS-SP1`、`24.03-LTS-SP2`、`24.03-LTS-SP3`、`22.03-LTS-SP4` 等；当前支持的版本以仓库 [社区版本分支名](https://atomgit.com/openeuler/release-management/blob/master/valid_release_branches.yaml) 为准。
- **软件包版本**：conda 中该软件包的版本号，如 `1.5.7`。
- **架构**：`x86_64`、`aarch64`等，与架构无关的包使用 `noarch`。

示例：

```yaml
24.03-LTS:
    1.5.7:
        - x86_64
        - aarch64
24.03-LTS-SP1:
    1.5.7:
        - x86_64
        - aarch64
```

## 四、贡献流程

1. **新增软件包**：在 `packages/` 下新建 `<package-name>/` 目录，按上述规范补齐 `package.yml` 与 `supported-versions.yml`，提交 PR。
2. **新增支持版本**：在已有软件包的 `packages/<package-name>/supported-versions.yml` 中追加新的 openEuler 版本 / 软件版本 / 架构，提交 PR。
3. **注意事项**：请确保 `name` 与目录名一致。

## 五、完整模板

### `packages/<package-name>/package.yml`

```yaml
# 软件包名，需与目录名、conda 包名保持一致
name: <package-name>
# 软件分类：others / hpc / storage / database等
category: others
# 软件包类型分类 RPM、应用镜像、CONDA、OEPKG、PIP、NPM、源码安装
type: CONDA
# 软件包简要描述（英文）
description: <one-line description of the package>
# 许可证标识（推荐 SPDX，如 BSD-3-Clause / MIT / Apache-2.0）
license: <SPDX-License-Identifier>
# 软件官网或项目主页
homepage: <https://example.com>

# 维护者账号与邮箱
maintainer: <your-account>
maintainer-email: <your-email@example.com>

# 使用说明（多行 Markdown）
usage: |

  - 添加Channel
    ```
    conda config --add channels conda-forge
    ```

  - 创建隔离环境(可选)
    ```
    conda create -n <package-name>
    conda activate <package-name>
    ```

  - 安装软件包
    ```
    conda install <package-name>
    ```

```

### `packages/<package-name>/supported-versions.yml`

```yaml
24.03-LTS:
    <package-version>:
        - x86_64
        - aarch64
24.03-LTS-SP1:
    <package-version>:
        - x86_64
        - aarch64
24.03-LTS-SP2:
    <package-version>:
        - x86_64
        - aarch64
24.03-LTS-SP3:
    <package-version>:
        - x86_64
        - aarch64
```
